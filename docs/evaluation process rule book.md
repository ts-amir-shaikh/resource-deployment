# Requirement Fulfilment Playbook — Resume Sourcing → Vetting → Submission
 
**Purpose.** Standard operating procedure for handling a client staffing requirement end to end, from intake to client submission. Run one thread per requirement, following these steps in order. This keeps every requirement (e.g., IndusInd .NET+Angular, ICICI Java/QA, Transbnk C2H) handled the same disciplined way.
 
**Golden rule.** Never inflate a candidate to fit the JD. Evidence comes only from the resume, the JD, and the client's written inputs. Distinguish verified fact from inference; label anything unconfirmed. A high score never hides a missing non-negotiable.
 
---
 
## Step 1 — Intake
 
Gather, for the specific requirement, both of:
 
1. **The requirement thread** (e.g., a Google Chat space thread) — the JD line, the shared resumes, and any discussion (availability notes, instructions).
2. **The client email context** — the original JD and every clarification the client gave (recruiter Q&A, feedback). Read the full thread; the email usually carries details the one-line JD omits (count, engagement length, exact location, onboarding window, domain, budget).
Keep one requirement = one thread so history and feedback stay isolated.
 
## Step 2 — Build the Effective JD
 
Merge the JD + client email into a single spec and classify each item as **Mandatory / Preferred / Good-to-have**:
 
- Role & exact stack (name the non-negotiables — e.g., "Angular v12+ AND .NET Core microservices in the same recent role")
- Experience band, number of positions, engagement type & duration
- Work location & mode (onsite/hybrid/remote, days/week)
- Onboarding window / notice preference
- Domain (mandatory vs preferable)
- Budget — note if the client asked *us* for a rate card (then budget is not a candidate screen)
- Any competitive pressure (e.g., "already interviewing other vendors" → speed matters)
## Step 3 — Vet Each Resume (evidence-based)
 
Read the **actual resume file**, not just the chat one-liner. For each candidate:
 
- **Snapshot:** name, total & relevant experience, current role, location, CTC/expected, notice/LWD, key skills.
- **Mandatory eligibility:** Meets / Partially meets / Does not meet / Not enough info — never mark met on a keyword alone.
- **Evidence-based skill mapping:** JD skill → resume evidence → match status. Same-role hands-on only.
- **Risks & gaps:** missing must-haves, keyword-without-evidence, job-hopping, unexplained gaps, seniority/domain mismatch, resume quality/English (for client-facing roles).
- **Score /100** (weighted to the JD) + **Confidence** (High/Medium/Low — reflects evidence quality, not candidate quality).
**Standing checks to always flag:**
- **Availability reality:** a past-dated Last Working Day means either "already available" or "stale profile" — confirm, don't assume.
- **Templated vs original CVs:** vendor-reformatted CVs (generic bullets, no employer names/dates, no named projects) are lower-verifiability — trust original exports more and request originals before believing skill lists.
- **The central non-negotiable:** confirm it's genuinely present across the pool; if none clearly have it (e.g., microservices), raise with the vendor/client before submitting.
## Step 4 — Shortlist & Recommend
 
Ranked comparison table (experience, stack match, domain, availability, score, confidence, key risk). Recommend which to validate for the open seats, plus backups. State the top validation points to close before submission.
 
## Step 5 — Reformat Selected CVs to the Client Template
 
Use the client's reference resume(s) as the **format**, candidate's original as the **content**. Standard rules:
 
1. **Name:** first name + last-name initial only (e.g., "Ashwini S").
2. **Remove personal details:** email, mobile, LinkedIn/links.
3. **Remove education.**
4. **Consolidate professional experience** into one company-free responsibilities block (no company-wise breakdown).
5. **Projects** in the reference structure: Title · Role · Languages · Frameworks/Architecture · Database · Responsibilities.
6. **Availability line:** past LWD → "Immediate"; still serving notice → actual notice period.
7. **Truthfulness:** do not insert JD keywords the source doesn't support; mark missing info in [brackets]; keep an "Information Requiring Confirmation" note to the internal team (not in the client copy).
**Apply client feedback as standing validation gates** for that requirement. (Example gate captured on IndusInd: *Angular must be explicitly visible in title, skills, experience, and projects.*)
 
Deliverable format: match the client's (PDF/DOCX). Verify the rendered output before sharing.
 
## Step 6 — Client Submission Email
 
Reply within the existing client email thread (reply-all to the same participants). Structure:
 
- Acknowledge any prior feedback and confirm it's addressed.
- List each attached profile: initials — experience — stack (lead with what the client asked for) — availability.
- Request review + feedback; offer to line up interview slots.
- Attach the reformatted CVs.
**Guardrails:** always create as a **draft first**; never send on the client's behalf without explicit confirmation. Attach the exported PDFs before sending.
 
## Step 7 — Feedback Loop
 
Capture each client response as a standing validation check for that requirement thread, then loop back to Step 3/5 for updated or additional profiles.
 
---
 
## Integrity checklist (before any submission)
- [ ] Nothing invented; every claim traceable to the source resume.
- [ ] Mandatory vs preferred separated; non-negotiables verified.
- [ ] Total vs relevant experience not confused; dates/overlaps checked.
- [ ] Missing info bracketed; templated-CV gaps flagged.
- [ ] Availability confirmed, not assumed from stale dates.
- [ ] No unsupported JD keywords added during reformatting.
- [ ] Client feedback gates applied.
- [ ] Email drafted, not sent; attachments included.

### Worked example (reference): IndusInd — Full-Stack .NET + Angular
- Effective JD: Angular v12+ **and** .NET Core microservices, 5–6 yrs, 2–3 seats, 6-month onsite contract (IBL House, Andheri East, 5 days/wk), onboard ~1 month, BFSI preferable; client asked us for the rate card (no budget given).
- Pool of 6 vetted; central gap = microservices unevidenced across all; one profile (Lahulesh) failed the Angular reality check and was dropped.
- Client feedback gate: "Angular nowhere mentioned in shared CV" → Angular made explicit in all reformatted CVs.
- Shortlist reformatted (Ashwini, Shobha, Ritik, Ketan) to the client template and submitted for review.
